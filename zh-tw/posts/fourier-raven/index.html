這篇文章在回答什麼？

核心問題：每個圓都只是等速旋轉，為什麼串在一起，能畫出烏鴉這麼不規則的輪廓？

背景知識：知道平面上的點可以寫成複數，以及 eiθ=cos⁡θ+isin⁡θe^{i\theta} = \cos\theta + i\sin\thetaeiθ=cosθ+isinθ 就夠了，其他會一步步說明。

閱讀路線：先玩一下圖，再依序看一個旋轉箭頭、許多箭頭相加、如何求出每個圓的大小，以及該留下多少個圓。

打開首頁時，一串旋轉的圓末端帶著一支筆，先畫出烏鴉的輪廓，接著才浮現 ASCII 畫像。這段動畫就是傅立葉級數：把一條封閉曲線寫成許多旋轉的總和。下面的圖使用和首頁相同的係數。調整圓的數量，看看輪廓如何變得清楚。

封閉曲線是時間的函數
#

想像用固定速度沿著烏鴉輪廓描一圈，整圈花一個單位時間。在每個時間 ttt，筆都有一個位置 (x(t),y(t))(x(t), y(t))(x(t),y(t))。把位置寫成一個複數，整幅圖就變成一個函數：

z(t)=x(t)+i y(t),0≤t<1.z(t) = x(t) + i\,y(t), \qquad 0 \le t < 1.z(t)=x(t)+iy(t),0≤t<1.

輪廓是封閉的，筆最後會回到起點：z(t+1)=z(t)z(t+1) = z(t)z(t+1)=z(t)。這條曲線是週期函數，而傅立葉級數描述的正是週期函數。

一個旋轉的箭頭
#

複數平面上最簡單的週期運動是

c e2πint.c\,e^{2\pi i n t}.ce2πint.

其中 ccc 是複數，nnn 是整數。當 ttt 從 0 走到 1，這個點會繞著一個圓移動：

  • 半徑是 ∣c∣|c|∣c∣；
  • 起始角度是 ccc 的輻角；
  • 一共轉 nnn 圈；nnn 為正或為負，旋轉方向相反；
  • n=0n = 0n=0 時完全不動，這一項決定整幅圖的中心。

把圖調成 1 個圓：筆只沿著一個圓移動。這是烏鴉最大的一項，n=1n = 1n=1，決定整圈的大小。

箭頭首尾相接
#

一個箭頭只能畫圓。想畫出更複雜的形狀，就把好幾個箭頭接起來：第二個箭頭的尾端接在第一個的尖端，第三個再接在第二個的尖端，依此類推。

在複數平面上，「首尾相接」其實就是加法：兩個複數相加，等於把代表它們的兩個箭頭接在一起。所以鏈條末端的位置，就是所有箭頭的總和：

z(t)=c0+c1e2πit+c−1e−2πit+c2e4πit+c−2e−4πit+⋯=∑ncn e2πint.\begin{aligned} z(t) &= c_0 + c_1 e^{2\pi i t} + c_{-1} e^{-2\pi i t} \\ &\quad + c_2 e^{4\pi i t} + c_{-2} e^{-4\pi i t} + \cdots \\ &= \sum_{n} c_n\, e^{2\pi i n t}. \end{aligned}z(t)​=c0​+c1​e2πit+c−1​e−2πit+c2​e4πit+c−2​e−4πit+⋯=n∑​cn​e2πint.​

每個箭頭仍然各自等速旋轉，但接在一起之後，末端畫出的路徑就比任何單一圓複雜得多。這個總和就是曲線的傅立葉級數，每個 cnc_ncn​ 決定其中一個圓的大小和起始角度。

先看最簡單的組合：在 n=1n = 1n=1 之外加上第二大的項 n=−1n = -1n=−1。它和第一個箭頭轉得一樣快，但方向相反。大箭頭轉一圈時，接在尖端的小箭頭朝反方向也轉一圈，筆尖於是被拉成一個橢圓：

求出每個圓的大小
#

現在把問題反過來：手上已經有烏鴉的輪廓 z(t)z(t)z(t)，要怎麼找出每個 cnc_ncn​？

關鍵是一個簡單的事實：一個轉了整數圈的箭頭，一整圈的平均位置是原點。它朝每個方向停留的時間一樣長，加起來互相抵消：

∫01e2πimt dt=0,m≠0.\int_0^1 e^{2\pi i m t}\, dt = 0, \qquad m \ne 0.∫01​e2πimtdt=0,m=0.

假設想求 c3c_3c3​。把整條曲線乘上 e−2πi⋅3te^{-2\pi i \cdot 3t}e−2πi⋅3t，相當於讓每個箭頭都往反方向多轉 3 圈：

  • 原本 n=3n = 3n=3 的箭頭，旋轉剛好被抵消，變成靜止不動的 c3c_3c3​；
  • 其他箭頭變成轉 n−3n - 3n−3 圈，仍然是不為零的整數圈。

再對一整圈取平均，所有還在轉的箭頭都平均成零，只剩下靜止的 c3c_3c3​。換成任何 nnn 都一樣：

cn=∫01z(t) e−2πint dt.c_n = \int_0^1 z(t)\, e^{-2\pi i n t}\, dt.cn​=∫01​z(t)e−2πintdt.

實際計算時，電腦手上沒有連續曲線，只有取樣點。首頁的輪廓取自 ASCII 烏鴉本身，沿著一圈取 N=2,048N = 2,048N=2,048 個點 z0,z1,…,zN−1z_0, z_1, \dots, z_{N-1}z0​,z1​,…,zN−1​，第 kkk 個點對應時間 t=k/Nt = k/Nt=k/N。把「一整圈的平均」換成「這 2,048 個點的平均」，積分就變成總和：

cn=1N∑k=0N−1zk e−2πink/N.c_n = \frac{1}{N} \sum_{k=0}^{N-1} z_k\, e^{-2\pi i n k / N}.cn​=N1​k=0∑N−1​zk​e−2πink/N.

這就是離散傅立葉轉換（DFT）。2,048 個點可以算出 2,048 個係數，快速傅立葉轉換（FFT）能一次有效率地算完。這一步在製作動畫時就做好了，你的瀏覽器只讀取算好的結果。

該留下哪些圓
#

2,048 個可能的項中，首頁保留 320 個。選法很單純：依半徑 ∣cn∣|c_n|∣cn​∣ 由大到小排序，留下最大的那些。圖中的頻譜也是按照這個順序排列。

理由來自 Parseval 定理。如果 zKz_KzK​ 只保留部分的項，兩條曲線的平均平方距離，剛好等於被捨棄的項的平方大小總和：

∫01∣z(t)−zK(t)∣2 dt=∑n 被捨棄∣cn∣2.\int_0^1 \bigl|z(t) - z_K(t)\bigr|^2\, dt = \sum_{n \text{ 被捨棄}} |c_n|^2.∫01​​z(t)−zK​(t)​2dt=n 被捨棄∑​∣cn​∣2.

每捨棄一項，誤差就增加它自己的 ∣cn∣2|c_n|^2∣cn​∣2，各項之間互不干擾。所以圓的數量固定時，留下最大的那些，平均平方誤差就最小。圖中的 RMS 與能量數值，都直接由這個等式算出。

圓不擅長畫什麼
#

平滑、緩慢彎曲的段落很省事，低頻就能描述得很好。鳥喙尖端、爪子和尾巴這類尖角就很費工：尖角會突然改變方向，只有轉得很快的箭頭才跟得上。圓太少時，每個尖角都會被磨圓；圓越多，尖角就越銳利。

所以頻譜有一條長長、緩慢變小的尾巴。最大的 32 項中，轉得最快的每圈轉 25 次；最大的 96 項中則是 68 次。再往後，部分保留的項每圈轉到 1,023 次，這是 2,048 個取樣點能表示的最高頻率。不過每圈超過 200 次的項，半徑都不到烏鴉高度的 0.004%，幾乎不影響畫面。

從公式到首頁
#

同樣的數學也影響了幾個工程上的選擇：

  • 首頁不在瀏覽器裡計算級數。 一個小腳本 generate_raven_path.py 事先把 320 項加總，將 2,048 個取樣點逐一存成 16 位元整數對，瀏覽器只需要解碼。
  • 首頁最多只畫 96 個圓。 半徑不到 0.2 像素的圓看不見。輪廓本身仍使用全部 320 項，省略小圓只是簡化示意圖。
  • 這一頁會在瀏覽器裡計算曲線，因為圓的數量由你決定。從最多 320 項重新算出 2,048 個點，最多只需要幾十毫秒。

圓上有圓
#

用圓上疊圓來畫圖，是很古老的想法。古代天文學家用本輪描述行星運動：一個小圓的圓心，沿著一個大圓移動。傅立葉級數是同樣的結構，只是圓可以要多少有多少。只要圓夠多，幾乎任何封閉路徑都能逼近。這種彈性說明了本輪為什麼能和觀測吻合，也提醒我們：吻合得好，不代表模型解釋了運動本身。

首頁的烏鴉不是行星，但原理相同：320 個各自等速旋轉的圓，就足以畫出它。
